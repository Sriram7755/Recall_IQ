Security Policy

Effective Date: July 12, 2026 • Powered by Sriii Technologies

At Sriii Technologies, our commitment to software security is absolute. The RecallIQ architecture enforces security best practices at rest, in transit, and during extension-page communication.

1. Data Encryption at Rest

When you log in using GitHub OAuth, we exchange the authorization code for an OAuth access token. Before writing this token to MongoDB Atlas, we encrypt it using the industry-standard AES-256-GCM (Advanced Encryption Standard in Galois/Counter Mode). * Each token is encrypted with a unique, randomly generated Initialization Vector (IV). * Encryption keys are injected dynamically in production via environment variables and are never hardcoded.

2. Data Transport Security

  • All network requests from the Chrome Extension popup, background service worker, and backend server utilize transport layer security (TLS/HTTPS).
  • Raw, unencrypted credentials or tokens are never transmitted over unencrypted HTTP channels.

3. JWT Authentication Model

To protect backend API endpoints, the application generates a secure JSON Web Token (JWT) on successful login. * JWTs are signed with a strong cryptographic key on the backend. * The Chrome Extension stores the JWT token locally inside chrome.storage.local. * All authenticated requests (dashboard metrics, repo list, save submissions) must provide the token in the Authorization: Bearer header. Any request lacking a valid JWT is blocked with a 403 Forbidden.

4. Reporting Vulnerabilities

If you discover any security issues or vulnerabilities in our extension or backend configuration, please do not open a public issue on GitHub. Instead, report it privately to our security team at security@sriii_technologies.com. We aim to address all verified reports within 48 hours.
